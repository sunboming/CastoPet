# Data-Driven Two-Level Wheel and Shortcut Launcher Design

## Goal

Extend CastoPet's radial interaction into a data-driven two-level wheel. The first level selects a feature category, while the second level selects an action within that category. The first release provides Expression and Shortcut Launcher categories.

Users can add launcher entries by dragging supported external items onto the pet. Shortcut configuration is local-only and managed from the existing settings window.

## Scope

### Included

- A two-level radial wheel driven by catalog data.
- First-level Expression and Shortcut Launcher categories.
- A 120 ms category dwell before opening the second level.
- Eight second-level slots per page, including pagination controls when required.
- Drag-and-drop registration of programs, files, folders, Windows shortcuts, and web links.
- Shortcut management in the settings window.
- Local persistence, duplicate prevention, validation, and launch error handling.
- Migration of the existing expression wheel without changing expression behavior.

### Excluded

- Running shortcuts as administrator.
- Treating arbitrary text as a shell command.
- General script execution support.
- Cloud synchronization.
- Automatic removal of missing targets.
- Quick notes, timers, and other future wheel categories.

## Interaction Design

The user presses and holds the right mouse button over the pet to open the first-level wheel. The first level initially contains Expression and Shortcut Launcher.

When the pointer enters a first-level category and remains there for 120 ms, its second-level ring expands outside the first ring. The user keeps holding the right mouse button, moves to a second-level item, and releases to execute it.

The active first-level category and active second-level item both receive the existing selected-state treatment: enlargement and visual highlighting. Moving the pointer back into the center closes the second level while keeping the first level open. Moving completely outside the wheel or pressing Escape cancels the interaction.

The second level has eight usable sectors per page. When the category contains more items than fit on one page, navigation sectors provide previous and next page actions. Navigation sectors consume visible slots, so every rendered page always has at most eight sectors and preserves usable target sizes.

If no shortcuts exist, the Shortcut Launcher second level shows a disabled instruction item indicating that items can be dragged onto the pet.

## Data Model

The radial UI consumes a generic catalog and does not contain expression-specific or shortcut-specific branching.

```text
WheelCatalog
  Categories: WheelCategory[]

WheelCategory
  Id
  DisplayName
  Icon
  Items: WheelActionItem[]

WheelActionItem
  Id
  DisplayName
  Icon
  ActionType
  ActionReference
  IsEnabled
```

The initial action types are:

- `ExpressionAction`, referencing an existing expression definition.
- `ShortcutAction`, referencing a persisted shortcut definition.
- Internal pagination actions generated by the wheel controller rather than persisted.

The model deliberately permits future action types, such as notes or timers, without changing radial layout code.

Shortcut data is represented separately:

```text
ShortcutDefinition
  Id
  Name
  Target
  Type
  Arguments
  WorkingDirectory
  IconSource
  SortOrder
```

Supported shortcut types are Program, File, Folder, WindowsShortcut, and WebUrl.

## Persistence

Shortcut definitions are stored locally at:

```text
%LocalAppData%\CastoPet\Shortcuts\shortcuts.json
```

Writes use a temporary file followed by atomic replacement. The service enforces a maximum of 128 entries.

If the JSON file is malformed, the service preserves it as a timestamped backup and loads an empty collection. A malformed individual entry is skipped and logged without preventing valid entries from loading.

Duplicate detection uses normalized identities:

- File-system targets use normalized absolute paths with Windows case-insensitive comparison.
- Web targets use normalized absolute HTTP or HTTPS URLs.
- A Windows shortcut is identified by its `.lnk` path rather than its resolved target, preserving shortcut-specific arguments and working-directory behavior.

## Components

### WheelCatalogService

Builds the runtime `WheelCatalog` from the current skin's expression definitions and the persisted shortcut collection. It publishes catalog changes when shortcut data changes.

### RadialWheelController

Owns wheel interaction state: opening, category dwell timing, second-level expansion, pagination, selection, cancellation, and action dispatch. Pointer geometry remains independent from action behavior.

### ShortcutService

Loads, validates, saves, adds, renames, reorders, and removes shortcut definitions. It owns duplicate detection and the 128-item limit.

### ShortcutDropHandler

Converts dropped content into shortcut candidates. It accepts:

- Executable programs.
- Ordinary files.
- Folders.
- `.lnk` Windows shortcuts.
- `.url` internet shortcuts.
- Direct browser drag data containing valid HTTP or HTTPS URLs.

Multiple dropped items are processed as one batch. The result reports added, duplicate, unsupported, and failed counts so the pet can show one concise response.

### ShortcutLauncher

Executes validated shortcut definitions through Windows shell behavior. Programs can use configured arguments and working directories. Files and folders use their default shell actions. Web links permit only HTTP and HTTPS schemes.

### Shortcut Settings Page

Adds a Shortcut Launcher section to the existing settings window. It shows each item's name, type, target, and validity state. Users can reorder, rename, delete, manually add a web URL, and configure program arguments and working directories. Its ordering is the wheel ordering.

## Data Flow

### Adding a shortcut

1. The pet receives drag data.
2. `ShortcutDropHandler` creates one or more candidates.
3. `ShortcutService` validates and normalizes them.
4. Existing normalized identities are rejected as duplicates.
5. Accepted definitions are persisted atomically.
6. `WheelCatalogService` rebuilds or updates the Shortcut Launcher category.
7. The pet displays a brief success, duplicate, partial-success, or failure reaction.

Original files are never copied, moved, renamed, or deleted.

### Launching an action

1. `RadialWheelController` resolves the selected second-level item.
2. It dispatches by registered action type.
3. Expression actions use the existing expression execution path.
4. Shortcut actions pass the referenced definition to `ShortcutLauncher`.
5. Failures produce a confused pet response and a local log entry.

## Error Handling and Safety

- Missing file-system targets remain configured and are marked invalid in settings.
- Invalid targets cannot crash the wheel or block other shortcuts.
- Only HTTP and HTTPS web schemes are accepted.
- Plain text is never interpreted as a command.
- No first-release path requests elevation or administrator access.
- The launcher uses structured target, argument, and working-directory fields rather than constructing a shell command string.
- Dragging unsupported data leaves the source unchanged and shows a short unsupported-item response.
- Configuration and launch failures are recorded in the existing local logging system.

## Compatibility and Migration

The existing eight expression entries become the Expression category's action items. Their ordering, assets, transition behavior, and execution path remain unchanged.

The current wheel visual style remains the baseline: translucent purple background, sector dividers, text labels, and enlarged selected sectors. The refactor changes its hierarchy and data source, not the established visual direction.

The catalog boundary becomes the supported extension point for future first-level categories. Future features should supply action definitions and handlers rather than add category-specific conditions to the wheel UI.

## Testing

Automated coverage must include:

- Catalog creation with Expression and Shortcut Launcher categories.
- Preservation of all existing expression items and ordering.
- The 120 ms dwell threshold and dwell cancellation.
- Opening and closing the second level by pointer movement.
- Cancellation by outer exit and Escape.
- Correct mapping for up to eight visible sectors.
- Pagination with no page exceeding eight sectors.
- Recognition of programs, files, folders, `.lnk`, `.url`, and direct HTTP/HTTPS drag data.
- Rejection of unsupported schemes and arbitrary command text.
- Path and URL normalization and duplicate detection.
- Atomic configuration round trips and malformed-file recovery.
- Maximum shortcut count enforcement.
- Reordering synchronization between settings and wheel catalog.
- Missing-target behavior and isolated launch failures.
- Regression coverage for expression selection and transitions.

Manual verification must cover pointer ergonomics at different pet positions, multi-item drag feedback, native program and folder launching, browser link launching, and settings-to-wheel refresh behavior.

## Acceptance Criteria

- A single right-button hold can navigate from the first-level category to a second-level action and execute it on release.
- Second-level expansion occurs only after approximately 120 ms of stable category selection.
- Shortcut pages remain usable and never display more than eight sectors.
- Supported external items can be added by dropping them onto the pet without changing the original items.
- Duplicate shortcuts are not added.
- Shortcut ordering and edits immediately propagate to the wheel.
- Existing expression behavior remains intact under the new catalog model.
- Invalid or missing targets fail locally and safely without terminating CastoPet.
